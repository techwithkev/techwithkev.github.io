1. Graph Representations: The Adjacency Matrix

A graph with n vertices is represented in memory by a n × n 2D matrix A, where entry A[i][j] stores the number of edges joining node i and node j. For an undirected graph, A is symmetric (A[i][j] = A[j][i]). In simple graphs, A[i][j] ≤ 1 and diagonal entries A[i][i] = 0 (no self-loops).

💡 CCC Contest Insights & Adjacency Lists
  • Adjacency Matrix vs. Adjacency List: For dense graphs where E ≈ V² (e.g. Floyd-Warshall O(V³)), an adjacency matrix is optimal because O(1) edge queries A[u][v] have zero pointer overhead.
  • Memory Overflow Trap: If V = 100,000 (standard in CCC Senior), a matrix requires 100,000 × 100,000 × 4 \text{ bytes} \approx 40 \text{ GB} of RAM, triggering an immediate Memory Limit Exceeded (MLE). You must use an Adjacency List (vector<int> adj[N]).
  • Matrix Multiplications & Paths: In graph theory, Ak[i][j] counts the exact number of walks of length k between node i and node j!
💻 Implementation Pattern
# Graph representations in Python
V = 5
# 1. Adjacency Matrix: O(V^2) space, O(1) edge check
adj_matrix = [[0] * V for _ in range(V)]

def add_edge_matrix(u, v):
    adj_matrix[u][v] = 1
    adj_matrix[v][u] = 1  # Symmetric for undirected

# Degree is the row sum:
def get_degree(u):
    return sum(adj_matrix[u])

# 2. Adjacency List: O(V + E) space (Essential for V > 5000)
adj_list = [[] for _ in range(V)]
def add_edge_list(u, v):
    adj_list[u].append(v)
    adj_list[v].append(u)
// Graph representations in C++
#include <vector>
#include <numeric>

// 1. Adjacency Matrix (V <= 2000)
const int MAXV = 500;
int adjMatrix[MAXV][MAXV];

void addEdgeMatrix(int u, int v) {
    adjMatrix[u][v] = 1;
    adjMatrix[v][u] = 1; // Symmetric
}

int getDegree(int u, int V) {
    int deg = 0;
    for (int j = 0; j < V; j++) deg += adjMatrix[u][j];
    return deg;
}

// 2. Adjacency List (Standard for V >= 100,000)
std::vector<int> adjList[100005];
void addEdgeList(int u, int v) {
    adjList[u].push_back(v);
    adjList[v].push_back(u);
}
// Graph representations in Java
import java.util.*;

public class GraphRep {
    // 1. Adjacency Matrix
    int[][] adjMatrix;
    public GraphRep(int V) {
        adjMatrix = new int[V][V];
    }
    public void addEdge(int u, int v) {
        adjMatrix[u][v] = 1;
        adjMatrix[v][u] = 1; // Symmetric
    }
    public int getDegree(int u) {
        int deg = 0;
        for (int val : adjMatrix[u]) deg += val;
        return deg;
    }
}
🎯 When to Use & Decision Criteria
Matrix vs List Selection

✔ When to Use Matrix

  • Dense Graphs: When E ≈ V², the O(V²) memory is fully utilized without pointer waste.
  • Small Vertex Count (V ≤ 2,000): Fits comfortably within the 256 MB or 512 MB contest memory limits.
  • Frequent Edge Existence Checks: Asking "Are u and v connected?" in exact O(1) time.
  • All-Pairs Shortest Path: Floyd-Warshall algorithm naturally operates over 2D cost matrices.

📋 Contest Scenarios

  • Matrix Powers for Path Counting: Finding the number of paths of exact length k via binary matrix exponentiation in O(V³ log k).
  • Grid / Maze Networks: 2D spatial mazes where neighbor connections are naturally row-and-column adjacent.
  • Transitive Closure (Warshall's): Finding if any reachable path exists between any two nodes.

❌ When NOT to Use

  • Sparse Graphs (V ≥ 10,000): Iterating through all neighbors of node u requires scanning all V entries in row u, degrading BFS/DFS from O(V + E) to O(V²) (TLE).
  • Massive Inputs (V = 100,000): Allocating a 100,000 × 100,000 array throws an instant Memory Limit Exceeded error. Always switch to an Adjacency List.

2. Fundamental Concepts: Degrees, K_n Proof & Trees

A graph G(V, E) has vertex set V of size n and edge set E of size m. Vertices u and v are adjacent if an edge connects them; the edge is incident to both endpoints. The neighbor set N(v) contains all nodes adjacent to v. Complete graphs Kn connect every pair of distinct vertices, containing exactly n(n − 1) / 2 edges.

💡 CCC Contest Graph Properties
  • The Handshaking Lemma: Since every undirected edge connects exactly two vertices, the sum of all degrees is always even (2m). Therefore, the number of vertices with an odd degree must be even!
  • Trees as Minimal Connected Graphs: A tree with n nodes always has exactly n − 1 edges and exactly one unique simple path between any pair of vertices. Adding any edge introduces a cycle.
  • Counting Subgraphs: The number of spanning trees in a complete graph Kn is given by Cayley's formula: nn-2.
💻 Implementation Pattern
# Graph properties in Python
def complete_graph_edges(n):
    # Kn has n*(n-1)//2 edges
    return n * (n - 1) // 2

def verify_handshaking(degrees, m):
    # Sum of degrees must equal 2 * m
    return sum(degrees) == 2 * m

def is_valid_tree_edge_count(n, m):
    # A connected tree with n vertices always has n-1 edges
    return m == n - 1
// Graph properties in C++
#include <vector>
#include <numeric>

long long completeGraphEdges(int n) {
    // Use 64-bit to prevent overflow when n > 65536
    return 1LL * n * (n - 1) / 2;
}

bool verifyHandshaking(const std::vector<int>& degs, long long m) {
    long long sumDegs = 0;
    for (int d : degs) sumDegs += d;
    return sumDegs == 2LL * m;
}
// Graph properties in Java
public class GraphTheoryUtils {
    public static long completeGraphEdges(int n) {
        return (long)n * (n - 1) / 2;
    }
    public static boolean verifyHandshaking(int[] degs, long m) {
        long sum = 0;
        for (int d : degs) sum += d;
        return sum == 2 * m;
    }
}
🎯 When to Use & Decision Criteria
Graph Invariants & Invariants

✔ When to Use Degrees & Formulas

  • Eulerian Path / Circuit Checks: Check if every vertex has an even degree (Eulerian circuit), or exactly 2 odd-degree vertices (Eulerian path).
  • Tree Quick Validation: Check if a graph is a tree by testing m = n - 1 and verifying it is connected via a single BFS/DFS.
  • Degree Sequences: Determining if a given sequence of numbers can form a valid simple graph (Havel-Hakimi Theorem).

📋 Contest Scenarios

  • Substation / Network Redundancy: Finding articulation points (cut vertices) and bridges where node degrees reveal critical bottleneck connections.
  • Complete Tournament Pairings: Round-robin tournament schedules where all n(n-1)/2 matches must be played.
  • Handshaking Parity Questions: Proving impossible conditions (e.g. Can 7 friends each have exactly 3 handshakes? No, 7 \times 3 = 21 is odd!).

❌ When NOT to Use

  • Assuming Edge Count Guarantees Acyclicity: An arbitrary graph with m = n - 1 is NOT necessarily a tree if it is disconnected (e.g. a triangle plus an isolated node). Always verify connectivity!
  • Multigraphs: Do not use simple Kn formulas for multigraphs where multiple edges exist between the same vertex pair.

3. Special Classes: Bipartite, Recommendation Graphs & Digraphs

A Bipartite Graph partitions vertices into two disjoint sets V1 and V2 such that every edge connects a node in V1 to a node in V2—no internal edges exist within the same set! A classic application is a User-Item recommendation system. In a Complete Bipartite Graph Kr, s, every vertex of V1 connects to all vertices of V2, having exactly r × s edges.

💡 CCC Contest Applications of Special Graphs
  • 2-Colorability / Bipartite Matching: In CCC problems, checking if a conflict graph is bipartite determines if participants can be separated into two teams without rivalries.
  • Maximum Bipartite Matching: Used for job-applicant assignment, dating apps, and bipartite matching using the Hopcroft-Karp algorithm or Max Flow (Dinic's).
  • Directed Graphs (Digraphs): In digraphs, degree splits into in-degree (incoming edges) and out-degree (outgoing edges). Vertices with in-degree = 0 are source nodes for Topological Sort!
💻 Implementation Pattern
# O(V + E) Bipartite Check using BFS in Python
from collections import deque

def is_bipartite(graph):
    n = len(graph)
    color = [-1] * n  # -1: uncolored, 0: Set A, 1: Set B

    for start in range(n):
        if color[start] != -1:
            continue
        queue = deque([start])
        color[start] = 0
        while queue:
            u = queue.popleft()
            for v in graph[u]:
                if color[v] == -1:
                    color[v] = 1 - color[u]  # Alternate color
                    queue.append(v)
                elif color[v] == color[u]:
                    return False  # Odd cycle detected!
    return True
// O(V + E) Bipartite Check in C++
#include <vector>
#include <queue>

bool isBipartite(int n, const std::vector<std::vector<int>>& adj) {
    std::vector<int> color(n, -1);
    for (int i = 0; i < n; i++) {
        if (color[i] != -1) continue;
        std::queue<int> q;
        q.push(i);
        color[i] = 0;
        while (!q.empty()) {
            int u = q.front(); q.pop();
            for (int v : adj[u]) {
                if (color[v] == -1) {
                    color[v] = 1 - color[u];
                    q.push(v);
                } else if (color[v] == color[u]) {
                    return false; // Odd cycle!
                }
            }
        }
    }
    return true;
}
// O(V + E) Bipartite Check in Java
import java.util.*;

public class BipartiteChecker {
    public static boolean isBipartite(int n, List<Integer>[] adj) {
        int[] color = new int[n];
        Arrays.fill(color, -1);
        for (int i = 0; i < n; i++) {
            if (color[i] != -1) continue;
            Queue<Integer> q = new LinkedList<>();
            q.add(i);
            color[i] = 0;
            while (!q.isEmpty()) {
                int u = q.poll();
                for (int v : adj[u]) {
                    if (color[v] == -1) {
                        color[v] = 1 - color[u];
                        q.add(v);
                    } else if (color[v] == color[u]) {
                        return false;
                    }
                }
            }
        }
        return true;
    }
}
🎯 When to Use & Decision Criteria
Graph Taxonomy Selection

✔ When to Model as Bipartite

  • Two Heterogeneous Entity Sets: Connections only exist between two distinct types of objects (e.g. Users ↔ Items, Students ↔ Courses, Doctors ↔ Hospitals).
  • 2-Coloring Feasibility: Problems requiring partitioning elements into two non-conflicting groups.
  • Grid Parity: Grids with coordinate parity (r + c) \pmod 2 form a natural bipartite graph between black and white chess squares!

📋 Contest Scenarios

  • Maximum Cardinality Matching: Pairing maximum number of applicants with jobs using augmenting paths (König's Theorem: Max Matching = Min Vertex Cover in bipartite graphs).
  • Knight's Tour / Domino Tilings: Every domino covers exactly 1 black and 1 white cell, translating grid tiling into bipartite matching.
  • Dependency Tracking (Digraphs): Course prerequisites and compiler task builds (DAGs, Topological Sorting).

❌ When NOT to Use

  • Graphs with Odd Cycles (Triangles, Pentagons): If a cycle of length 3, 5, 7 exists, the graph cannot be partitioned into two independent sets. 2-coloring will fail.
  • Peer-to-Peer Relationships: Social networks where friends can be friends with each other are general graphs, NOT bipartite.
