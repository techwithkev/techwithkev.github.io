1. Disjoint-Set Foundations & Uptrees

A Disjoint-Set data structure maintains a collection of non-overlapping sets. It supports three core operations: make(x) creates a set for x with parent[x] = x, find(x) climbs parent pointers to locate the root representative, and union(x, y) merges the trees containing x and y by attaching one root to the other. Without optimizations, naive union degrades tree depth to an inefficient O(N) linked list!

💻 Implementation Pattern (Naive)
# Naive Uptree Union-Find in Python
parent = [i for i in range(N)]

def find(x):
    while parent[x] != x:
        x = parent[x]  # Climbs up to root O(N)
    return x

def union(x, y):
    root_x = find(x)
    root_y = find(y)
    if root_x != root_y:
        parent[root_x] = root_y  # Naive attach
// Naive Uptree Union-Find in C++
#include <vector>

std::vector<int> parent;

void makeSet(int n) {
    parent.resize(n);
    for (int i = 0; i < n; i++) parent[i] = i;
}

int find(int x) {
    while (parent[x] != x) x = parent[x];
    return x;
}

void unite(int x, int y) {
    int rx = find(x), ry = find(y);
    if (rx != ry) parent[rx] = ry;
}

🎯 When to Use & Decision Criteria
Disjoint-Set Evaluation

✔ When to Use Disjoint-Sets

  • Dynamic Connectivity: Testing if two nodes belong to the same component while edges are being added on the fly.
  • Equivalence Classes: Grouping items based on symmetric, transitive relationships (A \sim B and B \sim C \implies A \sim C).
  • Kruskal's MST: Rapidly checking if adding edge (u, v) connects two already-connected components (cycle avoidance).

📋 Contest Scenarios

  • Offline Island / Grid Clustering: Merging water/land cells into connected components in linear time.
  • Friend Circles & Social Groups: Grouping students or users into mutual friend networks.
  • Percolation Thresholds: Tracking when liquid penetrates from the top row to the bottom row of a porous grid.

❌ When NOT to Use

  • Never use Unoptimized Naive Union: Always apply Path Compression and Union by Rank. Without them, union sequences like union(0,1), union(1,2), ... create an O(N) linked list that leads to Time Limit Exceeded (TLE) on competitive platforms.
  • Edge Deletions: Standard DSU only supports merging; it does NOT support removing edges. If edge deletions are required, use offline rollback DSU or dynamic trees (Link-Cut Trees).
Time: O(α(N)) ≈ O(1) Ackermann Bound: α(10⁸⁰) ≤ 4 Space: O(N)

2. Core Optimizations: Path Compression & Union by Rank

To prevent tall degenerate trees, two optimizations are applied simultaneously: Path Compression flattens the tree during find(x) by pointing all visited nodes directly to the root. Union by Rank attaches the root with the lower rank under the root with the higher rank, ensuring the tree remains balanced and never exceeds O(\log N) height. Together, they achieve an astonishing amortized complexity of O(α(N)), effectively constant time (≤ 4 ops for any practical universe size)!

💡 Why "Rank" Instead of "Height"?
  • Height Changes Dynamically: When Path Compression flattens a subtree, the true height of nodes decreases dramatically. Updating exact heights for all descendants would cost O(N), defeating the optimization!
  • Rank as an Over-Estimate: Instead of exact heights, we track an upper bound called rank. Path compression does not change the root's rank.
  • Logarithmic Height Guarantee: Even without path compression, Union by Rank alone guarantees tree depth ≤ \lfloor \log_2 N \rfloor. With both, runtime is practically linear for any conceivable dataset size.
💻 Implementation Pattern (Optimized)
# Optimized Union-Find in Python (Path Compression + Rank)
class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.rank = [0] * n

    def find(self, x):
        if self.parent[x] != x:
            # Path compression: rewire to root
            self.parent[x] = self.find(self.parent[x])
        return self.parent[x]

    def union(self, x, y):
        rx, ry = self.find(x), self.find(y)
        if rx == ry: return False  # Cycle!
        # Union by rank: lower rank under higher
        if self.rank[rx] < self.rank[ry]:
            self.parent[rx] = ry
        elif self.rank[rx] > self.rank[ry]:
            self.parent[ry] = rx
        else:
            self.parent[ry] = rx
            self.rank[rx] += 1
        return True
// Optimized Union-Find in C++
#include <vector>

struct DSU {
    std::vector<int> parent, rank;

    DSU(int n) : parent(n), rank(n, 0) {
        for (int i = 0; i < n; i++) parent[i] = i;
    }

    int find(int x) {
        if (parent[x] != x)
            parent[x] = find(parent[x]); // Path compression
        return parent[x];
    }

    bool unite(int x, int y) {
        int rx = find(x), ry = find(y);
        if (rx == ry) return false; // Cycle detected
        if (rank[rx] < rank[ry]) parent[rx] = ry;
        else if (rank[rx] > rank[ry]) parent[ry] = rx;
        else {
            parent[ry] = rx;
            rank[rx]++;
        }
        return true;
    }
};
// Optimized Union-Find in Java
public class DSU {
    int[] parent, rank;

🎯 When to Use & Decision Criteria
Optimized DSU Selection

✔ When to Use Both Optimizations

  • High Query Volumes (M ≥ 105): Essential in CCC Senior questions to ensure all operations complete within 0.1 seconds.
  • Any DSU Use Case: There is almost zero code overhead (just 2 extra lines), so you should always default to Path Compression.
  • Massive Graphs (V = 200,000): Guarantees stack recursion depth is virtually at most 2–3 levels, eliminating stack overflow crashes.

📋 Contest Scenarios

  • Kruskal's Algorithm: Sorting edges in O(M log M) and performing M find/union queries in O(M α(V)).
  • Subgrid Water Flow / Percolation: Dynamic connected components on large 1000 × 1000 matrices.
  • 2-SAT & Bipartite Validation: Maintaining parity sets (D-SU with offset weights).

❌ When NOT to Use Path Compression

  • Rollback DSU (Persistent DSU): When you need to undo unions (e.g. divide-and-conquer on queries, dynamic trees), path compression alters multiple parent pointers and cannot be easily undone! In persistent DSU, use Union by Rank alone (history stack stores only 1 change per union, allowing O(1) rollback).
Kruskal MST: O(E log E) Cycle Detection: O(α(V)) Greedy Selection

3. Cycle Detection & Kruskal's MST Algorithm

Union-Find provides the ultimate cycle-checking engine for Kruskal's Algorithm. To build a Minimum Spanning Tree (MST), edges are examined in increasing order of weight. For each edge (u, v): If find(u) == find(v), adding the edge would close an undesirable cycle and is rejected! If find(u) ≠ find(v), the edge connects two previously isolated components, is added to the MST, and union(u, v) is called.

💡 Kruskal's vs Prim's Algorithm
  • When Kruskal's Wins: Kruskal's algorithm is preferred on sparse graphs where E \ll V². Sorting edges takes O(E log E), and DSU lookups take O(E α(V)).
  • Early Termination: A spanning tree on V vertices is complete when exactly V − 1 edges have been added. You can immediately break out of the loop without checking remaining edges!
  • Connected Components Counting: Start with V components. Every successful union decrements component count by 1. When count hits 1, the entire graph is connected.
💻 Kruskal's Algorithm Pattern
# Kruskal's MST in Python
def kruskal(V, edges):
    # edges = [(weight, u, v), ...]
    edges.sort()
    dsu = DSU(V)
    mst_weight = 0
    mst_edges = []

    for w, u, v in edges:
        if dsu.union(u, v):  # Safe: No cycle!
            mst_weight += w
            mst_edges.append((u, v))
            if len(mst_edges) == V - 1:
                break  # MST complete
    return mst_weight
// Kruskal's MST in C++
#include <algorithm>
#include <vector>

struct Edge {
    int u, v, weight;
    bool operator<(const Edge& o) const {
        return weight < o.weight;
    }
};

long long kruskal(int V, std::vector<Edge>& edges) {
    std::sort(edges.begin(), edges.end());
    DSU dsu(V);
    long long totalWeight = 0;
    int count = 0;

    for (const auto& e : edges) {
        if (dsu.unite(e.u, e.v)) {
            totalWeight += e.weight;
            if (++count == V - 1) break;
        }
    }
    return totalWeight;
}
// Kruskal's MST in Java
import java.util.*;

public class Kruskal {
    static class Edge implements Comparable<Edge> {
        int u, v, weight;
        public int compareTo(Edge o) { return Integer.compare(this.weight, o.weight); }
    }
    public static long runKruskal(int V, List<Edge> edges) {
        Collections.sort(edges);
        DSU dsu = new DSU(V);
        long total = 0;
        int count = 0;
        for (Edge e : edges) {
            if (dsu.union(e.u, e.v)) {
                total += e.weight;
                if (++count == V - 1) break;
            }
        }
        return total;
    }
}
🎯 When to Use & Decision Criteria
MST & Cycle Check Selection

✔ When to Use Kruskal's + DSU

  • Sparse Graphs: When E \ll V², Kruskal's O(E log E) is faster and significantly easier to implement than Prim's.
  • Edge List Input: When input is given as a stream or list of weighted edges (u, v, w).
  • Minimum Bottleneck Spanning Tree: Finding a tree where the maximum edge weight is as small as possible.

📋 Contest Scenarios

  • Network Cable Connection: Connecting computers or cities with minimum total cost.
  • Maximum Spanning Tree: Simply reverse the sort order (sort descending) to maximize total edge weight.
  • Cycle Detection in Undirected Graphs: Quickly identifying if an undirected graph contains a cycle without performing full DFS traversals.

❌ When NOT to Use Kruskal's

  • Extremely Dense Graphs (E \approx V²): Sorting V² edges takes O(V² log V). Use Prim's Algorithm with an Adjacency Matrix in O(V²) time.
  • Directed Graphs: Kruskal's algorithm does NOT work for directed graphs. For Directed MST, you must use Edmonds' Algorithm (Chu-Liu/Edmonds).
