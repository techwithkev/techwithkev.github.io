1. Binary Search in Sorted Array

Instead of examining all $N$ elements sequentially ($O(N)$), binary search cuts the search space in half at each step by comparing the middle element against the target value. Halving $N=1,000,000$ items requires only $\approx 20$ comparisons!

💡 CCC Contest Insights
  • Preventing Integer Overflow: In C++ and Java, writing mid = (L + R) / 2 can overflow 32-bit signed integers if $L + R > 2^{31}-1$. Always prefer mid = L + (R - L) / 2.
  • Binary Search on Answer: In many CCC Junior/Senior problems (e.g. minimizing maximum distances, capacity checks), you binary search over the answer space instead of an explicit array.
  • Standard Library Shortcuts: In C++, use std::lower_bound (first element $\ge x$) and std::upper_bound (first element $> x$). In Python, use bisect.bisect_left.
💻 Implementation Pattern (Python)
# O(log N) Binary Search
def binary_search(arr, target):
    L, R = 0, len(arr) - 1
    while L <= R:
        mid = L + (R - L) // 2
        if arr[mid] == target:
            return mid  # Found target!
        elif arr[mid] < target:
            L = mid + 1 # Search right half
        else:
            R = mid - 1 # Search left half
    return -1       # Not found
Query Complexity: O(1) Build Complexity: O(N) Memory: O(N)

2. Prefix Sum Array (Range Sum Queries)

A Prefix Sum array precalculates cumulative sums so that the sum of any subarray from index $L$ to $R$ can be answered in exact $O(1)$ constant time using the formula $\text{Sum}(L \dots R) = P[R+1] - P[L]$. This eliminates repetitive $O(N)$ loop overhead for $Q$ queries.

💡 Why 1-Indexed Prefix Sums?

When using $0$-indexed prefix sums ($P[i] = \sum_{k=0}^{i} A[k]$), querying $L=0$ requires special-casing because $P[L-1]$ is out-of-bounds ($P[-1]$).

By defining $P$ with length $N+1$ and $P[0] = 0$:

  • $P[k]$ stores the sum of the first $k$ elements ($A[0 \dots k-1]$).
  • $\text{Sum}(L \dots R) = P[R+1] - P[L]$ works unconditionally without any if (L == 0) branch checks!
💻 Implementation Pattern (Python)
# Build 1-indexed Prefix Sum Array in O(N)
P = [0] * (len(A) + 1)
for i in range(len(A)):
    P[i + 1] = P[i] + A[i]

# Answer each range sum query in O(1)
def query_sum(L, R):
    return P[R + 1] - P[L]
Range Update Complexity: O(1) Final Reconstruct: O(N) Dual of Prefix Sum

3. Difference Array (Range Update Operations)

The mathematical dual of prefix sums. If you have $M$ operations that require adding $+V$ across a range $[L, R]$, updating the array naively takes $O(M \times N)$. A Difference Array reduces each range update to just two boundary operations in $O(1)$: $D[L] \mathrel{+}= V$ and $D[R+1] \mathrel{-}= V$. Then one final prefix sum restores all values in $O(N)$!

💻 Implementation Pattern (Python)
# Initialize Difference Array D
D = [0] * (N + 1)

# Apply range update [L, R] += V in O(1)
def range_add(L, R, V):
    D[L] += V
    D[R + 1] -= V

# Reconstruct original array in O(N)
A = [0] * N
A[0] = D[0]
for i in range(1, N):
    A[i] = A[i - 1] + D[i]
